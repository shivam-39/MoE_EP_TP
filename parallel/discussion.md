myAllreduce was ~1.1–1.2× slower than MPI.Allreduce (e.g. 0.00097s vs 0.00086s) because it uses a linear reduce-to-root plus broadcast (O(p) messages) while MPI uses a tree/ring algorithm and intra-node shared memory. myAlltoall was ~1.6× slower (e.g. 0.00104s vs 0.00066s) since it issues many small Python-level Sendrecv calls instead of one optimized collective; the extra cost is mostly latency and interpreter overhead on tiny messages, not extra bytes transferred.
